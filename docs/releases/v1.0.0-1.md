## 协议兼容性加固与安全修复

本版本集中在协议转换层的兼容性与健壮性，同时修复了一批安全与并发问题。没有不兼容的配置格式变更；Gemini / Antigravity 订阅登录已退役，详见下方「升级须知」。

### Gemini / Antigravity 订阅退役

- 移除 `gbx oauth gemini` 与全部 Gemini / Antigravity 推理代码。该后端不再提供模型发现、协议转换或工具调用。
- 已有配置和 `~/.gbx/auth` 下的凭据不会被删除。相关 provider 在启动时返回明确的 retired 错误，提示用 `gbx use` 选择其他提供方，或 `gbx use default` 回到 Grok Build 自带登录。
- Google Drive 云同步与 AutoClaw 不受影响，继续可用。

### 协议转换

- **错误与流式生命周期**：上游错误统一规范化为 OpenAI 错误结构；流开始前的校验失败仍返回正常 HTTP 错误码，流一旦开始就不再伪造错误帧；修正流式响应的结束标记与用量统计。
- **推理控制**：按模型解析推理档位并在越界时钳制到上游支持的范围；思考签名只回放给签发它的路由，避免跨提供方混用。
- **结构化输出与生成参数**：`json_schema`、`response_format` 及温度/采样参数按上游能力传递，不再被静默丢弃或改写。
- **消息拓扑**：修正多轮消息的角色顺序与合并规则，支持多模态 parts 与 annotations；有状态历史在重放时保持与原始请求一致的边界。
- **本地压缩**：Chat Completions、Anthropic Messages、Kiro、Qoder、Cursor、xAI 等没有 `/responses/compact` 的上游，现在由 gbx 在本地生成摘要压缩，返回可读的 `gbx1:` compaction item，不再向上游请求不存在的端点。
- **工具调用**：修正工具名的截断与别名分配、并行调用的结果槽位路由、缺失配对的孤儿调用；JSON Schema 规范化后再发送给上游。
- **Computer Use**：补齐 Codex Computer Use 的请求与结果格式，保留截图 detail；历史中最多缓存 6 张截图，避免上下文被图片占满。
- **模型发现**：`GET /v1/models/{id}` 返回单个模型（支持大小写不敏感、`[1m]` 后缀和含 `/` 的 ID），未知模型返回 404 `model_not_found`；provider 类型推断与能力声明现在与目录一致。

### 架构与安全

- 新增 `internal/paths` 统一 `~/.gbx` 下的数据、配置、缓存、凭据、代理与运行目录；新增 `internal/runtimelog` 负责结构化 JSONL 日志、保留策略与用量统计；`internal/selfupdate` 从 `cmd/update.go` 拆出；`internal/provider` 增加 OAuth 提供方元数据注册表，各子系统不再各自维护 switch。
- WebUI 拒绝任何含 `.git` 路径段的文件访问，大小写不敏感，并在符号链接解析前后各检查一次。
- Git 子进程固定传入 `-c core.fsmonitor=false -c core.hooksPath=/dev/null`，并从子进程环境清除 `GBX_SERVE_*`；`gbx serve` 启动后立即从进程环境移除 token，ACP、git、shell、MCP 子进程都无法继承。
- 会话 worktree 的 overlay 清单移出可写的 `.git` 目录，改为仓库外的 store 目录，删除前校验路径与清洁状态。
- WebUI 的工具事件在生成摘要前先脱敏，多文件编辑不再把 `diffs` 原文带进未经处理的事件字段。
- 协议探测与 `gbx doctor --probe` 使用同一套拒绝跨源重定向的 HTTP 客户端，API key 不会被重定向带到其他主机；`gbx serve` 打开的浏览器地址只接受 http/https。
- Google Drive 同步包解包按剩余配额限制单个条目的读取量，避免超大条目耗尽内存；同步注册表、同步状态与 Google OAuth token 使用跨进程文件锁；OAuth 回调校验 `state` 时使用常量时间比较，并拒绝非 GET 请求。
- 修复 Cursor 管道的写入死锁、帧交错与 protobuf 深度崩溃；Codex 网关修正关闭、快照与历史字节核算，目录刷新失败按 5 秒到 60 秒指数退避；修复 WebUI 会话删除与 worktree 清理的锁顺序、PID 复用导致的误判、导出 HTML 转义，以及网页终端的重连与 PTY 竞争。

### 命令行与 WebUI

- `gbx ls` 的 USED BY 列同时列出 `--with-provider` 绑定的额外提供方，与主提供方一起显示。
- 提供方名称校验统一：`gbx set`、`gbx provider cp/mv` 与 `gbx oauth <backend> [alias]` 采用同一套规则，拒绝 `/` 和大小写不敏感的 `default`。
- `gbx doctor` 的模型验证提示改为 `gbx provider models --probe`。
- WebUI 为配置的提供方维护预热的 Runtime 池：多个会话复用同一个本地 Responses 运行时，空闲 10 分钟回收；provider 配置、OAuth 登录或云同步拉取变更时让池失效。
- 会话索引改为内存索引加有界 LRU（最多 128 个打开会话，保留活跃与订阅中的会话），SSE 重连与健康检查不再重新扫描磁盘。
- 前端按需加载：`rehype-highlight` 只在消息含围栏代码块时加载（入口 JS 减少约 23.7%），字体只保留 latin woff2（字体体积减少约 48%），CodeMirror 语法按文件按需加载，文件/Git/设置/项目面板改为 `lazy`；内嵌前端资源从 3.10 MiB 降到 2.34 MiB。
- 修复 WebUI 若干状态问题：并发创建会话时只发出一个请求；对话流按会话和查看中的子 agent 重新挂载，切换后不再串用旧渲染状态；折叠的工具卡片不再渲染正文；文件面板的并发保存不会覆盖另一个已打开文件；登录轮询不会重叠请求或在卸载后写入状态；Git 面板的跳转焦点使用后被清除；切换面板后轮询使用正确的依赖。

### 升级须知

```bash
npm install -g @grokbuildx/gbx@1.0.0-1
gbx doctor
```

- Gemini / Antigravity 订阅不再可用，需要改用 `gbx oauth gpt|grok|qoder|kimi|kiro|workbuddy|autoclaw|cursor` 中的任一后端，或 `gbx use default`。
- Codex 守护进程协议版本保持 17。升级后若旧守护进程仍在运行，先执行 `gbx codex stop` 再 `gbx codex start`，确保使用新二进制。
- 配置格式、`~/.gbx/config.yaml` 与云同步文件与 1.0.0-0 兼容，无需迁移。
