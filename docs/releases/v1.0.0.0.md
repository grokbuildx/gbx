## gbx 1.0：围绕开源 Grok Build 重建（原 ccl）

本版本将项目从 ccl 更名为 **gbx**，并整体迁移到 [Grok Build](https://x.ai/cli)。这是不兼容升级，请先阅读下方「升级须知」。

### 完全开源：内置的 agent 就是你能读到的代码

- gbx（MIT）与它运行的 Grok Build agent（Apache-2.0）全部开源，没有任何闭源组件。
- macOS / Linux 版本固定使用 [xai-org/grok-build](https://github.com/xai-org/grok-build) 的开源提交（`third_party/grok-build/REVISION`，当前为 1.0.45 / `2bdd1d6a6369`），在公开的 GitHub Actions 中从源码编译，发布到 Release `grok-build-<提交>`。
- 每个 gbx 版本写死该 Grok Build 的提交与 SHA-256：首次启动时下载到 `~/.gbx/grok/rev-<提交>/` 并校验，校验失败拒绝使用；之后升级 gbx 只要固定提交不变，就不会重新下载。
- 启动内置 Grok Build 时关闭其自动更新，闭源的上游版本不会悄悄替换它。可用 `GBX_GROK_BIN` 指定其他 Grok Build。
- `gbx version` 同时显示 gbx 版本与内置 Grok Build 的版本、源码提交和下载状态；`gbx doctor` 显示实际使用的 Grok Build。

### Grok Build 与 Responses

- 终端启动、Codex 接入和 `gbx serve` 统一以 Grok Build 和 OpenAI Responses 为中心；Claude Code 启动器、Anthropic Messages 入口和 Zed OAuth 已移除。
- models.dev 混合网关按模型选择上游协议：Responses、Chat Completions，以及新增的 **Anthropic Messages**（`@ai-sdk/anthropic` 模型，例如各网关里的 Claude）。Messages 请求发往 models.dev 为该模型声明的地址，支持工具调用、图片、提示缓存和扩展思考，思考签名只回放给 Messages 路由。
- 每个 provider 可设置默认模型（`gbx set -m` 或 TUI 的 Default Model）。

### gbx serve 浏览器会话

- 重建 WebUI：项目文件与 Git 面板、网页终端、设置页，以及按会话持久化的历史。
- 新增操作系统沙盒开关：`gbx serve --sandbox workspace|off` 覆盖本次启动的新对话默认值，网页设置可修改并保存；关闭沙盒需要明确确认，已有对话保留创建时的模式。
- 子 agent 通过各自的会话流式输出，不会干扰主会话的用量和菜单；消息队列与「立即发送」重写；上下文用量在用量到达前也显示窗口大小。

### 升级须知（不兼容变更）

| 项目 | 旧 | 新 |
|---|---|---|
| 命令 | `ccl` | `gbx` |
| npm 包 | `@claudecodelaunch/ccl` | `@grokbuildx/gbx` |
| 配置目录 | `~/.ccl/` | `~/.gbx/`（**不自动迁移**） |
| 环境变量 | `CCL_*` | `GBX_*`（不再读取旧名） |
| Go 模块 | `github.com/claude-code-launch/ccl` | `github.com/grokbuildx/gbx` |
| 仓库 / 主页 | `claude-code-launch/ccl` | [grokbuildx/gbx](https://github.com/grokbuildx/gbx) / [grokbuildx.github.io](https://grokbuildx.github.io) |

旧版云同步文件格式不兼容，需在新版本中重新 `gbx cloud login` 并上传。

```bash
npm uninstall -g @claudecodelaunch/ccl
npm install -g @grokbuildx/gbx
gbx set            # 重新配置 provider（~/.ccl 不会被读取）
gbx version        # 确认 gbx 与内置开源 Grok Build 的版本
```
